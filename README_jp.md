# RegexPad

**Release: 1.1.0 (Stable)**

**リリース：1.1.0 安定版**

リリース日：2026年11月9日

[English](README.md) · [日本語の使い方](docs_jp/HOW_TO_USE_jp.md) · [English user guide](docs/HOW_TO_USE.md)

RegexPadは、Windows 11向けのポータブルテキストエディターです。
正規表現による検索・置換を中心に、HTML・CSS・WordPress記事のソースを
編集・確認するための機能を備えています。タブ編集、タグ挿入、構造チェック、
ローカルWordPressプレビューを、日本語・英語の画面で利用できます。

![日本語画面でWordPress記事を編集するRegexPad](docs/images/editor-ja.png)

## はじめに

1. 配布ZIPを、書き込み可能なフォルダーへ**すべて解凍**します。
2. `regex-pad.exe`、`module_cleaner.exe`、`_internal`を同じ構成で保持します。
3. `regex-pad.exe`を起動し、**ファイル > 開く**（`Ctrl+O`）で原稿を開きます。
4. 編集後は`Ctrl+S`で保存します。画面の言語は**言語**メニューで切り替えられます。

完全同梱版にはPython・QtとWordPressプレビュー環境が含まれます。
利用者がPython、WordPress、PHP、MySQL、Nodeを別途インストールする必要はありません。
ZIP内から直接起動せず、EXEだけを取り出さないでください。
管理者権限やレジストリー変更は不要です。

通常の編集はオフラインで利用できます。プレビュー環境を省いた軽量ビルドでは、
プレビューの初回実行時にインターネット接続が必要です。
完全同梱版はローカル環境を使いますが、記事内の外部画像・外部CSSなどは
参照先へ接続できる必要があります。

## 主な機能

| 分野 | 利用できる機能 |
|---|---|
| 編集 | 複数タブ・ウィンドウ、元に戻す／やり直し、文字コード選択、矩形コピー |
| 検索・置換 | Python `re`、除外条件、選択範囲・表示範囲指定、ハイライト、置換プレビュー |
| 正規表現補助 | 挿入メニュー、レシピ、日本語・英語リファレンス、構文の確認 |
| HTML・CSS | タグ・CSS挿入、文字色・背景色パレット、複数行タグの色分け |
| WordPress原稿 | Gutenberg構造チェック、ブロック属性内のJSONチェック、Markdown表・リスト変換 |
| プレビュー | WordPress経由の簡易HTML書き出し、Twenty Twenty-Fiveによる本格表示 |
| 復元・表示設定 | 自動バックアップ、保存前の世代バックアップ、復元、ルーラー、折り返し、空白可視化、配色 |

正規表現による検索・置換には、Python標準モジュールの`re`を使用しています。
メインウインドウのタイトルバーには、編集中のファイルのフルパスを初期設定で表示します。
**設定 > 表示 > フルパスを表示する**で切り替えられます。未保存タブの保存時は、
1行目を `.md` のファイル名候補として表示し、保存前に編集できます。
選択範囲限定をオフにしても本文の選択は維持されます。検索 / 置換を閉じると
マーカーは消えますが、開き直しても入力欄とチェック状態は保持されます。
検索すると、今回の一致箇所を編集画面の中央付近に移動してマークします。
検索・置換が成功すると、古いマーカー、プレビュー、選択範囲の参照を消します。
選択範囲限定で続ける場合は新しい範囲を選び直してください。
検索 / 置換には開いた元のファイル名が表示され、操作先はそのタブに固定されます。
別タブに切り替えても対象は変わらず、元タブを閉じると検索 / 置換も閉じます。

詳しい操作とショートカットは[日本語の使い方](docs_jp/HOW_TO_USE_jp.md)をご覧ください。
`Ctrl+U`では選択した文字を`<u style="">...</u>`で囲み、後からstyleを入力できます。
**設定 > ショートカットキー設定一覧**で変更可能なアプリのキーを変更し、定型文用のキーを追加できます。
変更不可の行は紫色の文字と灰色の背景で表示します。`Ctrl+N`、`Ctrl+O`、`Ctrl+S`、
`Ctrl+Shift+S`、`Ctrl+F`も変更できません。変更内容は`config.json`と同じ場所の
`shortcutkey_ref.json`に保存します。

## インライン色見本（現在のソース版）

オプションの **インライン色見本を表示** を有効にします。CSSの `#RRGGBB` の
直後にある色見本をクリックし、色を選んで **適用** を押すと、その1箇所のコードを
更新します。変更は1回の「元に戻す」で取り消せます。

## Unicode文字情報（現在のソース版）

文字を選択して**表示 > Unicode文字情報**を開くと、コードポイント、Unicode名、
分類、NFKC後の文字を確認できます。複数文字の選択では先頭の1文字を表示します。
未選択の場合はカーソル位置、文末では直前の1コードポイントを表示します。
結合記号もそれぞれのコードポイントで確認できます。
この操作で本文は変更されません。

## Unicode正規化置換

**検索 > 検索 / 置換**（`Ctrl+F`）から、検索条件に一致した文字列だけを
Unicode正規化できます。例えば、**正規表現として検索する**を有効にして
`[①-⑳]`を入力し、**Unicode正規化置換**、方式 **NFKC**、必要に応じて
**丸数字の変換後に「.」を付加**を有効にします。**置換**または
**すべて置換**を実行すると、`① ② ⑩ ⑳`を`1. 2. 10. 20.`へ変換できます。
このモードでは通常の「置換後の文字列」欄を使用しません。

| 方式 | 簡単な意味 | 主な動作 |
|---|---|---|
| NFC | 標準等価文字を合成 | 基本文字と結合文字を、合成済み文字がある場合にまとめる |
| NFD | 標準等価文字を分解 | 合成済み文字を標準的な構成文字へ分ける |
| NFKC | 互換文字を合成 | `①`を`1`へ、全角英数字を通常の英数字へ変換するなど |
| NFKD | 互換文字を分解 | 互換変換を行い、結果を分解された形で保持する |

正規化は文書全体ではなく、実際に一致した文字列ごとに適用します。
一致範囲外の文字は変更しません。ピリオド付加は、元の一致文字列が
`①`～`⑳`のいずれか1文字で、方式がNFKCまたはNFKDの場合だけ有効です。
互換正規化では見た目上の区別が変わる場合があるため、プレビューで対象を確認し、
方式が適切でなかった場合は「元に戻す」を使用してください。

## 検索/置換プリセット（現在のソース版）

プリセットエディターの**挿入辞書を編集**から、HTML、Markdown、WordPress、
段落・ショートカット定型文の辞書を編集できます。検証後、ユーザー用の
`user_dictionaries/`（または設定済みのユーザー辞書フォルダー）へ保存します。
Linterの基準辞書は編集対象に含めません。

**検索 > 検索/置換プリセット**から、新規作成、呼び出し・実行、編集、削除を選べます。
**検索 / 置換**画面の**今の検索/置換条件をプリセットする**を押すと、入力欄の内容と
チェック状態を1手順として編集画面に取り込みます。プリセット名を入力し、**保存**で
新しいJSONファイルを作成します。既定の保存先はアプリ横の`macro/preset_json_files/`です。
プリセット編集画面が開いている場合、空の最初の手順を埋めるか、既存の定義へ手順を追加します。
手順を追加・並べ替えて多段処理にもできます。
保存済みプリセットは編集画面で確認してから**実行プレビュー**を押し、結果を確認後に
**文書に適用**します。文書への適用は1回のUndoで戻せます。選択範囲・表示範囲の指定は
実行プレビュー時の対象文書に対して使います。削除したJSONは同じ場所の
`.deleted_presets`フォルダーに残します。

番号付きMarkdown見出しの下にある項目番号を変換するには、プリセットに手順を追加し、**番号付き見出しの下の項目番号を変換する**にチェックを入れます。検索・除外・置換欄はチェック中無効になり、入力済みの文字は解除後も残ります。文書の先頭から順に読み、`## 3.`の下の`1. 項目`を`## 3-1. 項目`に、`## 4.`の下では`## 4-1. 項目`に変換します。既存の項目番号と見出しの`#`の数を使います。番号のない見出しで対象区間を終了し、コードブロック内と字下げした行は変えません。この手順は文書全体を対象とし、プリセット形式3で保存します。旧形式のプリセットも引き続き読み込めます。

この機能はPythonから起動するソース版で検証済みです。変更後のEXEは未作成・未確認です。

## WordPressへ貼り付ける前の確認

現在のソース版では、**検索 > コアブロックチェック・修復**から、見出しの不足JSON、
ルート要素のクラス、一部のCSS宣言を補う候補を確認できます。
変更前後を見て候補を選び、適用すると、1回の「元に戻す」で戻せます。

**検索 > 文法チェック**（`F7`）で、現在のタブの**Error・Warning・Info**を確認できます。
結果をクリックして該当行を編集し、再チェックします。
オプションから、保存前のHTML・WordPress表記チェックも設定できます。

対象は、HTML・CSSの一般的な記述ミス、WordPressブロックの境界・親子関係、
ブロックコメント内JSONの構文と一部属性などです。
辞書と構造に基づく貼り付け前の確認機能であり、
ブラウザー全体の検証やGutenbergエディターの`save()`検証を完全再現するものではありません。

現在のソース版では、`wp:paragraph`の`fontSize`と`<p>`のフォントサイズクラスが
片側だけにある場合、静的な整合疑義として**Warning**を出します。段落と内側の
`<strong>`に文字サイズが共存する場合は編集上の注意を示します。`<u style>`には、
VS CodeのWordPress拡張機能で装飾が消えた実測に基づく別の**Warning**を出します。
`<u>`自体を禁止せず、WordPress本体のブロック検証結果とも区別します。

文法チェックとプレビューに、原稿の自動修復・自動書き換え機能はありません。
検索や置換プレビューも原稿を変更しません。
置換プレビューの行をクリックすると、元のタブの該当行へ移動します。
検索文字列を消すと、置換プレビューもすぐに消えます。
置換・正規表現書き換え・スニペット挿入・Markdown変換は、利用者が明示的に実行する編集操作です。
ファイル保存時には、選択された文字コードと改行コードの設定を適用します。

## 2種類のWordPressプレビュー

| モード | メニュー／ショートカット | 動作 |
|---|---|---|
| 簡易 | **表示 > WordPressプレビュー（簡易・自動終了）** · `Ctrl+Alt+P` | 現在の原稿を専用の中立テーマで描画し、HTMLを書き出して、そのプレビューのWordPressを終了してから表示 |
| 本格 | **表示 > WordPressプレビュー（Twenty Twenty-Five・本格）** · `Ctrl+Alt+Shift+P` | 標準テーマで描画し、再プレビューやフロント側の動作確認のためWordPressを起動したまま保持 |

簡易版は、WordPressコアのブロックCSSと記事内のスタイルを残し、
左右に全角約2文字分の余白を設けて本文を表示します。
書き出したページはWordPress終了後も閲覧できます。
JavaScript・イベント属性は省くため、それらの確認には本格版を使います。
本格版も同梱テーマとデモ環境による確認で、実サイトのプラグインは入っていません。

**原稿を変更したら、プレビューを再実行してください。**
実行のたびに未保存の編集内容をWordPressへ送ります。
古いブラウザーページの再読み込みだけでは、エディターの変更は送信されません。

起動から約10秒後、**準備済み**の簡易プレビュー環境をバックグラウンドで起動し始めます。
10秒は起動開始までの遅延時間で、使用可能になるまでの保証時間ではありません。
自動先行起動では不足資材をダウンロードしません。
状態はステータスバー右側の**WP**表示で確認できます。
本格版のWordPressは通常、そのRegexPadウィンドウと一緒に終了します。
先に止める場合は**表示 > WordPressを終了**を選びます。
簡易版の書き出しで、別に起動中の本格版を停止することはありません。

## 設定・バックアップ・削除一覧

設定はアプリの横の`config.json`、編集可能な色設定は`color_presets.json`に保存します。
既定のバックアップ先は`_internal`内です。
保存間隔・保持数・保持日数・保存済みファイルのバックアップ先は設定できます。

EXE初回起動時に、実際の保存先を記録した
`_internal/DELET_ITEMS_LIST.md`と`install_records/DELET_ITEMS_LIST.md`を作成し、
JSONの記録も保存します。共有される可能性のある参照先は、末尾の警告欄へまとめます。
記録するのはパスとパッケージ情報で、設定ファイルの内容は収集しません。

復元と整理の手順は、使い方ガイドの[バックアップと復元](docs_jp/HOW_TO_USE_jp.md#バックアップと復元)、
[保存場所と削除](docs_jp/HOW_TO_USE_jp.md#保存場所と削除)をご確認ください。
ポータブルフォルダーやプレビュー資材を削除する前に、必要な原稿・バックアップを保管してください。

## 開発者向け

ソース版はPython 3.12・PySide6を使用します。
このプロジェクトで指定されている環境で実行する場合は、PowerShellで次を使います。

```powershell
& "D:\Dev\venvs\venv_txt_edit312\Scripts\python.exe" main.py
```

検証も同じ環境で実施します。

```powershell
& "D:\Dev\venvs\venv_txt_edit312\Scripts\python.exe" -m pytest
& "D:\Dev\venvs\venv_txt_edit312\Scripts\python.exe" -m ruff check .
& "D:\Dev\venvs\venv_txt_edit312\Scripts\python.exe" -m pyright --pythonpath "D:\Dev\venvs\venv_txt_edit312\Scripts\python.exe"
```

`./build.ps1`はWordPress環境を準備して同梱します。
`./build.ps1 -SkipWordPressRuntime`では、初回プレビューで準備する軽量版を作成します。
最初の資材取得にはインターネット接続が必要です。
直接specを使う場合や実エンジン検証については、
[開発と配布](docs_jp/HOW_TO_USE_jp.md#開発と配布)をご覧ください。

ビルド時に`readme.txt`・`readme_jp.txt`と既存の`LICENSE.txt`も、
`regex-pad.exe`の横へコピーします。画像・リンクを保持するため、Markdown版README、
`docs/`・`docs_jp/`・`SCRIPT_STEPS.md`も同じ配布フォルダーへ含めます。
`LICENSE`・`SOURCE_CODE.md`・`THIRD_PARTY_NOTICES.md`と`LICENSES/`も同梱します。
ビルド処理はZIPを作成しないため、出力を確認してからフォルダー全体をZIP化してください。

ソースは`editor/`、`dialogs/`、`search/`、`fileio/`、
`settings/`、`preview/`に分離しています。
辞書と表示資材は`dictionaries/`、`resources/`にあります。

[作業記録](SCRIPT_STEPS.md)に検証内容と未確認の範囲を記録しています。
構造チェックを強化する背景となったGutenberg復旧処理の観察についても、
作業記録を参照してください。


## イベントを起点とする編集時の更新

検索条件を変えると、検索マーカーをその場で更新します。単純な文字列検索中の本文編集では、変更箇所の近くの一致だけを調べます。正規表現や範囲指定などの複雑な検索では、編集後の古いマーカーを消します。置換後もマーカーを消し、次に検索した時に付け直します。

WordPressブロックの既知の開始・終了コメントが壊れた場合と、編集中のブロック内のHTMLエラーを局所的に表示します。全文の文法チェックは「文法チェック」と保存時に実行します。WordPressプレビューの準備はプレビュー操作から始めます。バックアップは、入力時の最新復元データと、設定間隔ごとに作る未保存セッションの履歴を新しい順に10件保持します。
